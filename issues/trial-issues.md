## 问题清单

### 1. 数据集隔离失效（限定不守约）⏳待周末处理
- **现象**：检索限定 `--datasets aapm_videos` 时，结果仍混入文献库内容（如 SGRT 查询混入文献、proton 查询全混文献）。
- **场景**：想只在 AAPM 视频里查，结果带出了 wiki_full 文献，语义上违背"限定了就不该引入外"。
- **根因（已挖到源码层）**：cognee 1.4.2 的 dataset 隔离只挂在 `ENABLE_BACKEND_ACCESS_CONTROL=true`；
  而数据是单张扁平表存的（`DocumentChunk_text.lance`，所有数据集向量混在一起靠行内字段区分），
  关 access control 检索直接全表扫，`datasets` 参数被降级成元数据标注。
- **解决方向**：在②自研版里天然解决（LanceDB 按数据集分表 + 自写检索逻辑）；①版可选"检索后按 document_name 客户端过滤"（B 方案）或"重灌库开 access control"（A 方案）。
- **记录日期**：2026-08-12

### 2. 图谱 vs 全文的能力不对称（认知边界问题）🆕
- **现象**：cognee 图谱擅长"查具体知识点/顺着实体跳转"（带时间戳精准命中），
  但不擅长"概括一整场讲座讲了什么"（拼不出线性讲解脉络）。完整讲清一个 topic 得"图谱定位 + 全文读脉络"配合。
- **场景**：整理 AAPM 视频汇报时，靠图谱定位主题、还得回 transcript 读全文脉络。
- **反思**：图谱是"关联记忆"，不是"顺序阅读器"——这是架构天性，不一定是要修的 bug，而是**使用定位**问题。
- **解决方向**：②自研版可考虑"图谱定位 + 原子笔记/分段全文"双层存储，让两种查询都顺。
- **记录日期**：2026-08-12

### 3. 冒烟测试标题提取瑕疵 ✅（已修复 8/11 01:12）
- **现象**：检索结果标题没提取干净，`---` frontmatter 被当文本（部分显示"---"），"剂量预测"等标题没提出来。
- **场景**：query.py / smoke_test 结果展示时标题残缺。
- **解决**：query.py 的 extract_text 重写（剥 frontmatter/取#标题/去噪音），检索标题已干净。✅
- **记录日期**：2026-08-11

### 4. 图谱没自动接进回答流程（被动专业底色未真正落地）🔧核心
- **现象**：目前 cognee 图谱**还没自动接进我回答时的检索**——需我主动跑 query.py 才查。王成反复强调"别等事后查，要被动带出专业底色"。
- **场景**：王成直接问专业问题（放疗/LLM），应自动先查图谱，而不是等我手动触达。
- **解决方向**：把 kb_search(query.py) 接进"回答前自动检索"流程（AGENTS.md 第5条已立守则，但工具链未全自动）；②自研版核心目标。
- **记录日期**：2026-08-11（王成点破）

### 5. 多数据集检索 & 限定隔离 ⏳
- **现象**：①cognee.search 的 datasets 传逗号字符串不行（需拆列表，已修✅）；②限定单数据集仍混串（见第1条，未解决）。
- **场景**：跨 wiki_full+github_projects 融合检索已通；但"只查某一数据集"不干净。
- **解决方向**：②自研版按数据集分表；①版客户端过滤或重灌。
- **记录日期**：2026-08-11/08-12

### 6. 部分文献来源元数据不全 ⏳
- **现象**：部分文献（英文综述/M2M 英文版）frontmatter 没存 journal/DOI，抓不到精确出处。
- **场景**：标记 📚 来源时，这些条目标注不完整（只有标题没期刊/DOI）。
- **解决方向**：根源是源文献元数据不全，灌库时未补齐；②阶段考虑规范化 frontmatter（统一补 journal/DOI/year）。
- **记录日期**：2026-08-11

### 7. 图谱视觉扁平、缺层级纵深感 🆕王成观察
- **现象**：王成觉得建立的图谱看着是扁平的不是三维/立体的。确认真实：visualize.py 用 networkx+spring_layout（力导向）把所有节点摊在 2D 平面，感官上是"铺平的网"，无纵向层次感。
- **查证**：数据层面其实有维度——cognee 节点有 5 类（Entity 14035 / DocumentChunk 4533 / EntityType 2954 / TextSummary 303 / TextDocument 303），且每节点带 topological_rank（文档→分块→摘要→实体有层级）；只是 visualize.py 只画 Entity 类高频节点，把类型/层级维度舍弃全压平面。
- **本质**：知识图谱是图结构（拓扑网），不是真三维网格；"想要立体感"=期望看到层级/聚类/维度分层，而非 3D 旋转模型。
- **解决方向**（②自研版）：①可视化按 topological_rank/节点类型分层布局（高维概念上、底层事实下）或带聚类分组；②主动联想支持"顺关系跳转 + 沿层级上下钻取"；③ZenBrain 7层记忆天然带层级结构（Working→…→Cross-Context），②自研比 cognee 更该make出纵深感。
- **记录日期**：2026-08-12
